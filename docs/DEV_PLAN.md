# 개발 기획서 — 봉안함 원격 참배·AI 추모 대화 MVP (0단계 시연 프로토타입)

기준 문서: `bongan-remote-memorial-plan.md` (내부 검토용 초안 v0.1, 2026-09-19)
목표: **사찰·운영자 앞에서 직접 눌러 보는 시연**. 카메라 1대(개발용 웹캠) → 칸 좌표 등록 → 내 칸 보기 → 추모 공간 → 기념일 대화(B등급, 음성 대화)까지 전 과정을 한 노트북에서 돌린다.

---

## 1. MVP 범위 결정

계획서 화면 목록(유족 6 + 관리자 5)을 전부 넣되, 각 화면은 "시연에 필요한 최소 동작"까지만 만든다.

| 기능 | MVP에서 하는 것 | MVP에서 안 하는 것 (파일럿 이후) |
|---|---|---|
| 원격 참배 | 10초마다 갱신되는 내 칸 사진, 30초 실시간 보기(MJPEG), 사람 감지 시 자동 차단 | WebRTC, 카메라 55대 운용, PoE IP카메라 |
| 봉안함 누르기 | 관리자가 카메라 화면 위에 사각형을 그려 봉안함 번호와 연결 | 자동 칸 인식 |
| 옆 칸 보호 | 현장 프로그램에서 내 칸 밖 흐림 처리 후 송출. 원본은 서버·휴대폰에 가지 않음 | — |
| 추모 공간 | 고인 사진·생몰일·방명록·다가오는 기일·영상 메시지(업로드) | 영상 메시지 자동 제작(HeyGen 등) |
| 기념일 대화 (B등급) | 기억 카드 기반 LLM 대화, 안전 점검(위기·재산·의료·법률), AI 표시 상시 노출, 15분 제한, 요약만 저장, 사진 아바타(숨쉬기·말할 때 움직임) | 실시간 립싱크 아바타(A등급) |
| 음성 입출력 | 브라우저 음성 인식(Web Speech API) + 브라우저 음성 합성(0원) + **ElevenLabs 복제 음성**(키 입력 시) | 수퍼톤(국내) 공급자 |
| API 키 관리 | 관리자 콘솔에서 입력·마스킹·연결 테스트 (Anthropic, ElevenLabs) | 키 암호화 저장(KMS) |
| 제사 일정·중계 | 일정 등록·알림 목록, 중계 URL 임베드 또는 현장 카메라 MJPEG | HLS 서버, 카카오 알림톡 |
| 공양·헌화 신청 | 신청·접수 상태 관리 (결제는 모의) | 국내 PG 정기결제 |
| 가족 초대·설정 | 초대 링크 발급(카카오톡으로 보낼 URL), 대화 기능 작별(자료 반환·삭제) | 카카오 로그인, 휴대폰 본인확인 |
| 관리자 콘솔 | 칸 좌표 도구, 계약·가족, 고인 프로필·기억 카드·동의서, 의례 일정, 이용 현황 | 정산 |

## 2. 기술 스택 (설치 없이 바로 도는 구성)

| 층 | 선택 | 이유 |
|---|---|---|
| 서버 | Python 3.12 · FastAPI · uvicorn | 현장 프로그램(OpenCV)과 같은 언어. 이미 설치되어 있음 |
| DB | SQLite (WAL) | 설치 0. 파일럿에서 PostgreSQL로 교체 (스키마는 그대로 이식 가능) |
| 현장 프로그램 | OpenCV(웹캠 캡처·잘라내기·흐림), HOG 사람 감지(내장, 모델 파일 불필요) | 서버로 **밖으로 나가는 HTTP만** 사용 — 계획서의 망 분리 원칙 유지 |
| 유족 웹앱 | 정적 HTML + Vanilla JS (모바일 우선, 큰 글씨, 한 화면 버튼 3개 이내) | 빌드 없음. 카카오톡 링크로 바로 열림 |
| 관리자 콘솔 | 정적 HTML + Canvas(칸 좌표 도구) | 동일 |
| LLM | Anthropic SDK (`claude-opus-5`) — 키가 없으면 규칙 기반 Mock으로 자동 전환 | 공급자 교체 가능한 인터페이스(`server/ai/base.py`) |
| STT/TTS | 브라우저 Web Speech API | 0원, 시연에 충분. TTS 공급자 인터페이스만 준비 |
| 실시간 영상 | MJPEG over HTTP (30초 세션) | WebRTC는 파일럿 |

React가 아닌 Vanilla JS를 택한 이유: 시연 프로토타입은 "돌아가는 것"이 우선이고, 화면 11개가 모두 단순 CRUD·이미지 표시라 프레임워크 이득이 작다. 파일럿에서 팀이 붙으면 API는 그대로 두고 프런트만 React로 옮긴다.

## 3. 시스템 구성 (MVP)

```
[웹캠] → edge/agent.py ──(HTTP, 밖으로만)──▶ server/ (FastAPI, :8000)
           │ 캡처·사람감지                     ├─ /api/edge/*    현장 업로드
           │ 칸별 잘라내기+흐림                 ├─ /api/family/*  유족 앱 API
           │ 10초 사진 / 라이브 5fps           ├─ /api/admin/*   관리자 API
           └ 원본은 서버로 보내지 않음(관리자 좌표용 전체 화면만, 사람 없을 때)
                                               ├─ /             유족 웹앱
                                               ├─ /admin        관리자 콘솔
                                               └─ ai/           LLM·안전점검 (교체 가능)
```

## 4. 데이터 구조 (SQLite)

facilities → rooms → cameras → niches(code, x,y,w,h)
contracts(niche_id, holder) → family_members(role: view/chat/manage, invite_token)
deceased(contract_id, memory_card, ai_enabled) → consents, media, guestbook
rituals(facility 또는 contract 단위) → offerings
chat_sessions(summary, safety_events) · audit_logs

## 5. 인증 (MVP)

- 유족: 초대 링크 `/?t=<token>` — 토큰이 가족 구성원·권한·계약·칸을 결정. 카카오톡으로 링크만 보내면 된다.
- 관리자: `X-Admin-Key` (환경변수 `ADMIN_KEY`).
- 현장 프로그램: `X-Edge-Key` (환경변수 `EDGE_KEY`).
- 파일럿에서 카카오 로그인·휴대폰 본인확인으로 교체.

## 6. 안전장치 구현 위치

| 계획서 요구 | 구현 |
|---|---|
| AI 표시 상시 노출 | 대화 화면 상단 고정 배너 + 시작 시 고지 모달 |
| 위기 신호 → 109 안내 | `server/ai/safety.py` 키워드·패턴 검사 → 고인 역할 중단, 정해진 문구 |
| 재산·의료·법률 차단 | 같은 모듈, 정해진 응답 |
| 아무것도 팔지 않음 | 시스템 프롬프트 금지 조항 + 공양 신청 메뉴는 대화 화면 밖 |
| 15분 제한 | 서버가 세션 시작 시각 기준으로 종료. 클라이언트 타이머는 표시용 |
| 첫 이용 49재 이후 권장 | 사망일 +49일 이전이면 안내문 표시(차단은 하지 않음, 관리자 설정) |
| 미성년자 보호자 동반 | 세션 시작 시 확인 체크 |
| 음성 원본 미보관 | STT는 브라우저에서 처리, 서버는 텍스트만 받고 요약만 저장 |
| 작별 절차 | 설정 화면 → 마지막 인사 → 자료 반환/삭제 → ai_enabled=0, 동의 철회 기록 |
| 동의서 | 관리자 등록, 유효 동의 없으면 대화 시작 불가 |

## 7. 일정 (계획서 0단계 4~6주에 맞춤)

| 주차 | 산출물 | 상태 |

| 2 | 추모 공간, 방명록, 제사 일정, 공양 신청, 가족 초대 | **이번 착수분** |

| 5~6 | 음성 복제 공급자 1곳 연동 시험, 실시간 아바타 시연, 제사 중계 시험 | 다음 |

## 8. 실행

```
pip install -r requirements.txt
python -m server.seed          # 시연 데이터
python -m uvicorn server.main:app --port 8000
python -m edge.agent           # 별도 창, 웹캠 캡처
```
자세한 사용법은 README.md.
